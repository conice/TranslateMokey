# iOS 27 界面设计要点与规范

## 状态与适用范围

- 资料核对日期：2026-11-05；来源为 Apple 官方 iOS 27 页面、Human Interface Guidelines（HIG）与 Liquid Glass 适配文档。
- 本文区分 iOS 27 已确认变化、跨版本通用指导与项目建议；HIG 为持续更新文档，不将其中所有内容视为 iOS 27 新增。
- 本文为设计参考，不代表真机验证或用户验收；实现与验证状态以 [v0.4.0 实施说明](v0.4.0.md)为准。
- 核心方向：延续 Liquid Glass，让内容优先、操作层清晰，并加强可读性，而不是把整个界面做成透明玻璃。

## 1. iOS 27 已确认变化

Apple 官方 iOS 27 页面明确列出以下变化。右栏是据此整理的设计建议，不是官方逐字规范。

| 官方变化 | 设计建议 |
| --- | --- |
| Liquid Glass 折射更均匀 | 不依赖局部强烈折射来区分控件或表达状态 |
| 改善对比度与可读性 | 文字、图标清晰度优先于透明效果 |
| App 图标更加锐利、细节更清晰 | 保证小尺寸识别，不只追求装饰细节 |
| 新增 Liquid Glass 外观滑块，可从高度透明调至完全着色 | 适应系统偏好，不假设所有用户看到相同透明度 |

这些变化不意味着所有界面有统一的圆角、模糊半径或阴影参数。来源：[Apple — iOS 27](https://www.apple.com/os/ios/)。

## 2. 视觉层级与材质

### 内容层与操作层

HIG 指导：

- 内容层包括正文、图片、列表、表单和内容卡片，以常规背景或标准材质组织信息。
- Liquid Glass 主要用于导航与操作层，例如导航栏、标签栏、工具栏及重要浮动操作。
- 不要将 Liquid Glass 广泛铺在内容层，否则会削弱内容与操作之间的区别。内容层中的滑块、开关等控件，其临时交互元素可在激活时使用玻璃外观来强调交互性。
- 自定义玻璃效果应克制，优先使用已经具备系统外观和行为的标准组件。

项目建议：阅读界面的文章保持清晰稳定，玻璃效果用于导航和阅读工具，不用于每个段落的背景。

### Liquid Glass 类型选择

| 类型 | 适用场景 | 注意事项 |
| --- | --- | --- |
| `regular` | 大部分导航、操作控件，以及文字较多的界面 | 通过背景模糊和明暗调整保障可读性，通常优先选择 |
| `clear` | 浮在照片、视频等丰富视觉内容之上的控件 | 不是通用默认值，必须评估背景变化后的对比度 |

对于明亮媒体背景上的 `clear`，Apple 建议视情况增加 35% 不透明度的黑色遮罩。背景足够暗，或标准媒体控件已提供遮罩时，无须重复添加。这是特定场景建议，不是所有玻璃组件的固定参数。

来源：[HIG — Materials](https://developer.apple.com/design/human-interface-guidelines/materials)。

## 3. 导航、工具栏与弹层

以下属于当前系统设计指导，不能全部视作 iOS 27 首次新增。

- 导航与操作分工明确：标签栏切换主要目的地，工具栏提供当前内容相关操作。
- 工具栏按功能分组：处理同一对象或执行相关动作的按钮放在一起，不把所有按钮塞进同一组。
- 常见操作可使用标准图标：每个图标都应提供无障碍标签；共享背景的同一组工具栏项目，避免随意混搭纯文字与纯图标。
- 搜索使用系统语义：若搜索是标签栏的一部分，使用系统搜索标签，让系统处理位置和分离方式。
- Sheet 保留上下文：系统半屏 Sheet 与屏幕边缘留有间距，扩展至全高时会更不透明；不要覆盖系统背景来强行固定外观。
- 检查圆角与安全区：弹层边角附近的文字、按钮不能贴边，底部内容不能被浮动栏或键盘遮挡。

来源：[Apple — Adopting Liquid Glass](https://developer.apple.com/documentation/technologyoverviews/adopting-liquid-glass)。

## 4. 排版、尺寸与颜色

### 尺寸与对比度基线

| 项目 | 官方依据或项目建议 |
| --- | --- |
| 默认文字尺寸 | HIG 列出 iOS、iPadOS 默认文字尺寸为 17 pt，不是所有文字统一 17 pt |
| 最小文字尺寸 | HIG 列出 11 pt，不应把它当成正文或重要信息的常用尺寸 |
| 默认控件尺寸 | 当前 HIG 列出 44 × 44 pt |
| 最小控件尺寸 | 当前 HIG 同时列出 28 × 28 pt；不要误写成所有控件硬性最小 44 pt |
| 项目触控建议 | 高频操作优先提供至少 44 × 44 pt 的可点击区域，并避免相邻目标过密 |
| 项目对比度建议 | 普通正文采用至少 4.5:1 的验收基线；大字等适用情形按对应无障碍标准评估，不能任意降低要求 |

原生尺寸单位为 `pt`，不是截图像素 `px`。图标可见尺寸与点击区域不是同一个概念；网页布局也不能直接拿截图像素当作 CSS 尺寸。

### 字体与颜色规则

- 优先使用系统字体和语义文字样式，通过层级、字重与留白组织信息。
- 支持 Dynamic Type；放大字体后允许换行和布局重排，而不是裁切关键文字。
- 中文界面检查中英混排、数字、标点和多行文本，不用固定行高强行套用英文版式。这是项目排版建议。
- 优先使用系统语义颜色，适配浅色、深色及增强对比度设置。
- 错误、成功、选中状态不能只靠颜色，还需文字、图标或形状提示。
- 透明材质上的对比度必须结合实际背景检查，不能只在单色设计稿上验收。

来源：[HIG — Typography](https://developer.apple.com/design/human-interface-guidelines/typography)、[HIG — Accessibility](https://developer.apple.com/design/human-interface-guidelines/accessibility)。

## 5. 图标、形状与动效

### 图标

- 原生界面的常规操作优先采用 SF Symbols，保持图标与相邻文字的尺寸、字重协调。
- 避免仅凭难以理解的自定义符号承载重要功能。
- 不要把图标更清晰理解为增加装饰与纹理越多越好。

### 形状

- 优先沿用系统控件的圆角、胶囊形状和容器关系。
- 自定义组件需考虑内外轮廓、间距与内容密度，不应给所有卡片机械套同一个大圆角。
- 本次核对的资料没有提供适用于所有 App 的统一圆角、阴影、模糊数值；具体项目值应标注为自定义设计变量。

### 动效与性能

- 动画用于解释状态变化、操作反馈和元素之间的关系，不是持续装饰。
- 响应系统 Reduce Motion，减少自动、重复的缩放与位移动画。
- 多个自定义玻璃元素需关注合成与滚动性能；原生实现可利用 `GlassEffectContainer` 合并效果。
- 本次核对的资料没有规定统一动画时长；不要将某个毫秒数标注为 iOS 27 官方标准。

依据为前述 Typography、Accessibility 与 Adopting Liquid Glass 文档；具体自定义形状与动效参数属于项目设计决策。

## 6. 网页与用户脚本适用边界

### Apple 官网字号核对与项目取值

2026-11-05 读取官网 CSS（不是浏览器实测截图）：[基础样式](https://www.apple.com/v/homepage/a/styles/main.built.css)、[全局导航](https://www.apple.com/api-www/global-elements/global-header/v1/assets/globalheader.css)、[首页样式](https://www.apple.com/v/homepage/a/styles/homepage.built.css)。以下为相应选择器的声明，不代表所有页面组件的最终计算字号。

| 类型 | 桌面 | 手机断点 |
| --- | --- | --- |
| 基础 body | 17px | 同一基础声明 17px |
| 小正文 / 普通按钮 | 14px / 14px | 同一基础声明；具体组件可覆盖 |
| 全局导航文字 | 12px | ≤833px 展开菜单 28px，不是正文 |
| promo 宣传标题 / 副标题 | 40px / 21px | ≤1068px 为 32px / 19px |

本次按 [Apple 首页](https://www.apple.com/) 引用重新核对基础样式：`body` 声明 17px、约 1.47 倍行高、400 字重；`h1`–`h6` 声明 600 字重，中文 `:lang(zh)` 不压缩字距。以下为项目适配值，不是 Apple 官方组件规范。

TranslateMokey 是工具面板，不照搬宣传标题或手机大菜单。项目取值：正文及按钮 14px、导航与提示 13px；页面标题 24px / 1.2、设置折叠标题 16px / 1.5、分节标题 18px / 1.3，三者均为 600 字重且不压缩字距；页面标题下留白 24px，分节标题上下留白 32px / 16px。词条标题仍为 18px、复习词 24px；查询译文标准 16px，随译文字号设置缩放。桌面输入 14px，≤600px 手机输入保留 16px，降低 iOS 输入聚焦自动放大的风险；点击目标仍至少 44px。手机实际缩放行为待真机验证。

网页译文默认保持宿主字号的 100%，采用 400 字重系统字体、1.5 倍行距、上下各 0.6em 留白，不压缩字距、不降低透明度；颜色跟随宿主页面，以适应明暗背景，不强制使用官网浅色页面的深色正文。预览和实际译文共用样式生成函数。已保存的字号、行距、间距与颜色不被覆盖；新安装、缺省字段或点击“恢复网页阅读显示默认”采用新默认。字体栈、字距和透明度为统一渲染样式，不是存储设置。

以下为网页适配边界，不是通过验证的兼容承诺；具体实现以版本说明为准。

- 可借鉴内容层级、排版和操作布局，不将原生组件 API 当成浏览器可用能力。
- CSS `backdrop-filter` 只是近似视觉效果，不等同于原生 Liquid Glass；需要考虑不支持模糊效果时的可读背景降级。
- 不假设网页能读取或跟随原生 Liquid Glass 外观滑块；系统偏好在浏览器中的可访问能力与实际表现待核实。
- 网页文本缩放不等于原生 Dynamic Type，需要在目标浏览器验证字体放大、布局重排和控件可达性。
- 模糊背景、阴影和动画不能干扰宿主网页阅读，也不能使移动设备的滚动性能明显下降。
- 平台字体、图标资源的使用应符合各自许可，不因本文推荐原生系统资源就直接复制进网页。

## 7. 交付前验收清单

以下为待执行清单，未勾选不代表已经测试失败，也不表示已经通过。网页项目按上一节核实平台能力，不将原生系统行为自动算作支持。

- [ ] 玻璃主要用于导航和操作，没有大面积铺在正文、列表和内容卡片上。
- [ ] 浅色、深色、明亮图片和复杂背景下，文字与图标均清晰。
- [ ] 调整 Liquid Glass 外观偏好后，层级和状态仍然明确；网页端记录该偏好是否实际影响界面。
- [ ] 开启减少透明度、增强对比度、减少动态效果后，界面仍可用，并记录平台支持边界。
- [ ] 最大无障碍字号或目标浏览器文本缩放下，关键文字和操作没有被截断。
- [ ] VoiceOver 能读出控件名称、作用和状态，焦点顺序合理。
- [ ] 小屏、横屏、键盘弹出及安全区变化时，没有遮挡和无法触达的按钮。
- [ ] 加载、空内容、错误、禁用、选中等状态均有明确设计。
- [ ] 在目标设备验证滚动和动效，不只验收静态截图。
