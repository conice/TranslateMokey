# TranslateMokey

面向桌面与手机浏览器的用户脚本（油猴脚本）翻译工具，结合自定义翻译 API、网页双语阅读、生词本与网页词义标注。

## 文档状态与范围

- 当前版本为 v0.4.4，支持保存并切换多个自定义 API 与词典，API Key 按 API 独立保存；内置 Index API 与微软 Bing 词典只读，地址、模型、解析脚本和凭据在界面、日志及导出中脱敏。生词本词条的单词、释义与详情入口合并为单行，AI 查询结果已在生词本时收藏图标显示实心星；沿用 v0.4.3 的标注与网页阅读显示微调、统一查询、快捷菜单及设置自动保存能力。当前实现、安装方式与验收边界见 [v0.4.x 实施说明](docs/v0.4.0.md)，不代表第三阶段全部完成或已经发布。
- 用户明确提出的需求：支持自定义 API、内置 Index Translate 服务配置、自动识别源语言并翻译成目标语言、生词本、在网页单词后显示收藏释义，同时兼容桌面与手机浏览器。
- 第一阶段核心闭环与第二阶段网页阅读的代码范围已实施；第三阶段分批推进，跨设备同步尚未接入。
- 本文是本项目的产品蓝图，不是某个现有竞品的功能核实报告。
- 已只读核查 Tampermonkey 文档及相关 Issues、同类开源项目；来源与设计取舍见实施说明。未实际调用翻译接口，接口能力、服务条款和浏览器兼容性仍待核实。

## 1. 翻译服务与 API 管理

### 内置 Index Translate

根据用户提供的 `Index-Translate.py` 示例提取以下配置，不包含原文件中的凭据：

| 项目 | 示例配置 |
| --- | --- |
| 服务地址 | `https://index-translate.bilibili.com/v1` |
| 模型 | `index-mt-9b` |
| 调用方式 | OpenAI 兼容的 `chat.completions` |
| 消息形式 | 在用户消息中指定目标语言并提供待翻译文本 |
| 附加请求体 | `{"chat_template_kwargs":{"enable_thinking":false}}` |

“内置”指将服务配置和调用逻辑移植到 JavaScript，不是在浏览器中运行 Python。原示例存在导入语句、缩进与括号问题，不作为可直接运行的实现。

界面中的内置 Index 配置只读，不显示服务地址、模型或凭据；用户可添加多个自定义 API，并从下拉框选择当前使用项。自定义 API 保存服务地址与 API Key 后可自动拉取模型，也可手动填写模型 ID。

示例设置了 `User-Agent: Mozilla/5.0`，但是否必需、脚本管理器是否允许设置，均待核实，不预先承诺沿用。鉴权要求、模型可用性、语言覆盖、请求限制和浏览器端可用性也待核实。

### 功能规划

- 自定义 OpenAI 兼容接口：填写服务地址、API Key、模型及必要请求参数；凭据由用户提供，不内置到发布脚本。
- 多服务配置：保存、命名、复制和切换配置。
- 连接测试：经用户触发发送最小测试文本，展示响应时间和具体失败原因，并提示会向服务发送请求。
- 模型设置：支持手动填写；服务提供相应能力时可读取模型列表。
- 用途分配：全文翻译、划词翻译、词典解释可分别选择服务。
- 请求控制：配置超时、并发数、请求间隔和分段大小。
- 失败处理：限流等待、有限重试、取消请求和失败段落重试。
- 备用服务：可选故障切换，默认关闭；不得未经用户确认将内容转发到其他服务。
- 用量统计：记录请求数与字符数；仅在服务提供实际 token 用量时记录 token，不伪造费用。
- 扩展适配：成熟阶段按明确协议增加非 OpenAI 服务，不假设所有 API 只修改地址即可兼容。

## 2. 语言识别与目标语言

- 自动源语言：结合实际文本、页面语言提示和上下文判断，不只依赖网页的 `lang` 属性。
- 手动源语言：允许纠正短词、专名和混合语言的识别歧义。
- 全局目标语言：设置默认阅读语言，并可临时切换而不修改默认值。
- 网站级语言：为特定网站指定源语言或目标语言。
- 混合语言处理：按段落或文本块判断，不强制整页只有一种源语言。
- 跳过规则：配置已掌握语言；源语言与目标语言相同时避免无效翻译。
- 能力提示：语言选择列表不等于服务实际支持范围；支持情况以服务核实结果为准。

自动选择源语言进行翻译，不等于接口能返回准确的语言标签。若界面展示“识别为某语言”，必须有可靠结果支撑；服务是否支持返回识别结果待核实。

## 3. 网页全文翻译

- 一键翻译、恢复原文，支持原文下方显示译文的双语模式。
- 仅译文模式：隐藏原文但保留恢复能力。
- 段落操作：单独翻译或重新翻译某段。
- 可见区域优先、滚动按需翻译，避免默认发送全部页面内容。
- 动态页面支持：处理无限滚动、异步加载和单页应用更新。
- 保留页面结构：尽量保留标题、列表、表格、链接和强调样式。
- 内容过滤：默认跳过代码、输入框、编辑器、脚本和样式。
- 状态反馈：显示等待、翻译中、完成和失败状态。
- 暂停与取消：停止排队任务，避免页面切换后插入旧译文。
- 缓存复用：文本、服务、模型、语言和翻译规则一致时复用结果。
- 网站规则：按网站设置自动翻译、手动翻译或禁用。
- 译文样式：调整字号、颜色、行距及原译文区分方式。

## 4. 划词与即时翻译

- 支持单词、短语、句子，并按内容长度提供合适的结果展示。
- 可结合所在句子进行上下文翻译，明确提示上下文也会发送给服务。
- 桌面提供选区翻译按钮，以及翻译、关闭结果、收藏等快捷键。
- 手机提供适合触摸的选区入口，不依赖鼠标悬停。
- 提供手动输入或粘贴入口，作为无法可靠获取选区时的替代方式；不自动读取剪贴板。
- 支持复制原文或译文、重试、切换目标语言。
- 支持固定结果卡片，避免轻微触摸导致结果立即关闭。
- 从翻译结果加入生词本，允许收藏前编辑释义。

## 5. 词典与解释

- 基础释义：词性、常见含义、当前上下文中的含义。
- 词形信息：原形、复数、时态等，依据语言与数据源能力提供。
- 发音信息：音标及可用的发音播放。
- 例句与译文：优先保存当前网页中的真实例句。
- 扩展解释：常见搭配、近义词、反义词、短语、习语及专名。
- 来源标识：区分词典数据、模型生成解释与用户编辑内容。

当前内置微软 Bing 词典只读，界面与查询确认不显示其 URL 或解析脚本；支持添加多个自定义 JSON/JS 词典并选择当前使用项。发音使用浏览器提供的本地语音，具体边界见 v0.3.0 实施说明。模型生成的音标、词形和例句不视为权威词典数据。

## 6. 生词本管理

- 收藏单词和短语，不限于单个英文单词。
- 保存原词、源语言、目标语言、确认后的释义、例句、来源标题与链接、收藏时间。
- 多义项管理：同一词可保留不同语境中的含义。
- 词形关联：成熟阶段支持词形与原形关联，例如 `running` 与 `run`，允许手动纠正。
- 编辑词条：修改释义、例句、备注和词形。
- 重复处理：重复收藏时提示合并或补充例句。
- 分类与标签：按主题、用途或学习内容组织词条。
- 搜索、筛选与排序：按语言、标签、收藏时间和学习状态查询。
- 批量操作：修改标签、导出和删除，破坏性操作需确认。
- 学习状态：未学、学习中、已掌握。
- 误删恢复：提供回收站或撤销机制。
- 数量与容量统计：展示词条数量及存储占用。

初期使用用户脚本管理器存储，在同一浏览器环境、同一脚本的不同网页间共享。持久化 API 及容量限制需按目标管理器验证，不预设具备跨设备同步能力。

## 7. 网页生词释义标注

默认理解：只标注生词本已有词条，不自动查询网页里的每一个词。

收藏 `robust → 稳健的` 后，网页呈现效果：

> This approach is robust〔稳健的〕.

### 显示与交互

- 即时开启或关闭，无须重新加载页面。
- 显示形式：词后括号、下划线与词义卡片、仅高亮。
- 桌面支持悬停或点击；手机通过点击查看完整词条。
- 标注频率：每页首次、每段首次或每次出现。
- 已掌握词可隐藏或淡化。
- 提供网站级关闭和限制规则。

### 匹配与更新

- 默认显示收藏的简短释义，不在每次匹配时请求 API。
- 完整词匹配与大小写策略，避免将 `art` 匹配到 `partial`。
- 短语优先，避免长短语被多个单词标注拆开。
- 第一阶段以精确匹配为主；词形扩展作为后续可选能力，不假设所有语言规则相同。
- 按源语言和目标语言选择词条，不误用其他目标语言的释义。
- 多义词默认使用用户选定含义，需要上下文判断时由用户主动触发。
- 增量处理动态加载内容，避免重复插入；词条修改后更新标注。
- 只处理合适的正文文本，跳过输入框、代码块、脚本、样式及已有标注。
- 关闭时移除脚本标注，保留原页面内容与事件行为。
- 与全文翻译协同，默认只标注原文，不在脚本生成的译文内重复匹配。

中日韩分词、英文词形变化和跨 HTML 标签的短语匹配需要分别设计，不能依赖单一正则表达式解决。

## 8. 复习与学习

本模块属于成熟阶段扩展，不作为翻译功能的前置条件。

- 每日复习列表和可配置的学习数量。
- 间隔复习，根据学习反馈安排下次复习。
- 正反面卡片：看原词回忆释义，或看释义回忆原词。
- 例句填空与拼写练习。
- “认识／模糊／不认识”反馈。
- 已掌握词重新加入复习。
- 学习记录：新增、复习和掌握数量。
- 待复习提示，不承诺浏览器关闭后仍能准时提醒。

## 9. 历史与数据管理

- 可选翻译历史：开启后可搜索、复用和删除。
- 缓存管理：查看大小、设置保留策略和手动清理。
- JSON 完整备份：保留词条结构和数据格式版本。
- CSV 导出：方便表格处理，不承诺复杂字段无损往返。
- 学习工具导出：按明确格式导出给 Anki 等工具，不等于自动同步。
- 导入校验与预览：提示非法字段、重复词条和预计变更。
- 冲突处理：选择跳过、合并或覆盖；覆盖前确认。
- 设置导入导出：默认排除 API Key 和敏感请求头。
- 存储升级：迁移旧版本数据，考虑失败恢复。
- 可选跨设备同步：单独设计服务、冲突处理和隐私保护，不依赖本地存储自动实现。

## 10. 桌面与手机界面

桌面与手机从初期共同设计，不把手机适配留到产品完成后。

视觉与交互参考见 [iOS 27 界面设计要点与规范](docs/ios-27-design.md)，其中区分官方指导与项目取值；本次已实现范围及真机验收边界见 [v0.4.x 实施说明](docs/v0.4.0.md)。下表仍为产品规划，不是已验证清单。

| 场景 | 桌面 | 手机 |
| --- | --- | --- |
| 功能入口 | 浮动按钮、脚本菜单、快捷键 | 可收起浮动按钮、脚本菜单 |
| 翻译结果 | 定位浮窗或侧栏 | 底部面板，必要时全屏 |
| 生词本 | 宽屏列表与详情 | 单列列表与独立详情 |
| 词义标注 | 悬停或点击 | 点击展开，提供明确关闭入口 |
| 设置 | 分组面板 | 单列设置页 |
| 选区不可用 | 快捷键或手动输入 | 手动粘贴入口 |

共同要求：

- 浅色、深色和跟随系统主题。
- 支持大字号、文本缩放及足够大的触摸区域。
- 适配窄屏、横竖屏切换和屏幕安全区域。
- 手机软键盘弹出时，关键输入内容和按钮仍可访问。
- 浮动按钮位置可调整，减少遮挡网站导航。
- 支持键盘导航、焦点管理和读屏标签。
- 隔离脚本界面样式，减少与网站 CSS 冲突。

## 11. 浏览器兼容边界与验收

兼容单位是“浏览器 + 用户脚本管理器 + 版本”。以下是候选覆盖范围，不是已通过测试的兼容清单。

| 平台 | 候选覆盖范围 | 当前状态 |
| --- | --- | --- |
| 桌面 | Chrome、Edge、Firefox 的主流用户脚本环境 | 待选择组合并实测 |
| 桌面 Safari | 支持用户脚本的扩展环境 | 单独核实与验证 |
| Android | 能安装并运行用户脚本管理器的浏览器 | 待选择组合并实测 |
| iOS / iPadOS | Safari 与可用用户脚本扩展 | 扩展能力待核实与实测 |

不支持用户脚本扩展的手机浏览器，不能仅靠一个 `.user.js` 获得同等功能。独立网页或原生扩展属于其他产品范围。

验收项目：

- 跨域请求、存储、脚本菜单和更新机制。
- 桌面选区、手机选区、触摸事件、页面缩放和软键盘交互。
- 长页面、无限滚动、单页应用以及前后台切换。
- iframe、Shadow DOM 和严格页面安全策略下的限制。
- 脚本界面与网站布局的隔离，以及关闭翻译或标注后的页面恢复。

浏览器内部页面、部分内置 PDF 阅读器、画布文字及受限页面不保证可处理。跨域请求计划使用 `GM_xmlhttpRequest` 或目标管理器支持的对应 API；权限声明与实现必须按实际管理器验证。

## 12. 隐私与安全

- 首次发送请求前说明服务接收方与文本范围。
- 整页自动翻译需用户主动开启，提供网站白名单和黑名单。
- 默认排除输入框、编辑器和密码字段，避免收集草稿。
- 已保存的 API Key 不回填界面，不进入日志或普通导出文件；新 Key 只在编辑输入框中短暂接收。脚本本地存储不等于加密保险箱，GM 存储中的自定义 URL、解析脚本和 Key 不是加密数据。
- 内置 API 与词典的地址、模型、解析脚本和凭据在界面摘要、联网确认、状态提示、日志及导出中脱敏；自定义配置的名称可用于确认请求接收方，但不会显示其 URL 或 Key。
- 默认使用 HTTPS，不静默转发到其他服务。
- 将翻译结果和导入内容视为不可信数据，防止 HTML 注入。
- 自定义配置允许填写参数，不允许直接执行任意代码。
- 清空数据、覆盖导入等破坏性操作必须明确确认。
- 诊断信息默认脱敏，不自动上传日志。

## 13. 稳定性与维护

- 模块分离：翻译服务、生词存储、页面标注和界面分别承担明确职责。
- 可取消任务队列：避免页面切换后继续消耗额度。
- 错误分类：区分鉴权失败、限流、网络问题及返回格式异常，不吞掉错误。
- 性能控制：增量扫描与批量处理，重点验证手机长页面不卡顿。
- 缓存失效：更换服务、模型、目标语言或翻译规则后避免使用不匹配结果。
- 多标签页一致性：词条与配置变更同步到其他已打开页面。
- 升级支持：提供版本说明、数据迁移和兼容性提示。
- 测试覆盖：接口适配、导入导出、词条匹配、DOM 恢复和真实浏览器交互。

## 14. 建议开发阶段

| 阶段 | 建议范围 |
| --- | --- |
| 第一阶段：核心闭环 | Index 预设、自定义 OpenAI 兼容接口、自动源语言与目标语言、划词翻译、生词本、词后释义、JSON 备份；同时完成桌面与手机布局，并验证选定的浏览器组合 |
| 第二阶段：网页阅读 | 双语全文翻译、动态页面、队列与缓存、网站规则、标注频率与样式、扩大兼容性测试 |
| 第三阶段：成熟学习工具 | 词形与多义项、词典与发音、复习系统、更多服务协议、可选跨设备同步 |

第三阶段已按 v0.3.0 启动实施，首批范围与后续边界见实施说明。代码完成、自动化测试通过、安装验证、用户验收和发布授权分别记录，不互相替代。

## 15. 暂不纳入核心范围

- 图片 OCR 与扫描 PDF 翻译。
- 视频字幕翻译。
- 语音对话。
- 输入框写作翻译。
- 不支持用户脚本环境下的独立应用或原生扩展。

这些能力需要单独评估技术路线、外部服务、隐私和成本，不作为现有规划的隐含承诺。

## 16. 开发前待核实事项
